# 具身数据飞轮

面向实验室场景（真机遥操作采集 + Isaac Sim 仿真生产）的完整数据飞轮：从采集完毕的初始数据，到数据处理、质量评估、训练验证、反向优化采集的闭环。

核心理念：**数据质量的最终裁判是"训出来的模型好不好用"，其他一切指标都是代理指标（proxy）。**

## 0. 全景图

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  采集        │ → │  处理        │ → │  质检/评测   │ → │  入库/版本化  │
│ (遥操作/仿真) │   │ (清洗/对齐/  │   │ (人工+自动)  │   │ (数据资产)   │
│             │   │  切片/标注)  │   │             │   │             │
└─────────────┘   └─────────────┘   └─────────────┘   └──────┬──────┘
      ↑                                                       ↓
      │                                               ┌─────────────┐
      │                                               │  训练 + 评测 │
┌─────────────┐   ┌─────────────┐                     │  (闭环验证)  │
│  采集优化    │ ← │  缺口分析    │ ←───────────────────└─────────────┘
│ (任务/场景/  │   │ (失败归因/   │
│  操作员培训) │   │  覆盖度缺口) │
└─────────────┘   └─────────────┘
```

## 1. 采集环节：质量在采集时就被决定了

### 1.1 真机遥操作（机械臂 / VR 人采）

每条 episode 除传感器数据外，必须记录**质检元数据**：

| 类别 | 内容 |
|---|---|
| 传感器流 | RGB（多视角）、深度、关节状态（position/velocity/torque）、末端位姿、夹爪开合、力/触觉（如有） |
| 动作流 | 下发的目标位姿/关节指令（训练标签） |
| 时间戳 | 每帧硬件时间戳，所有流共同时钟基准 |
| 元信息 | 操作员 ID、任务描述（语言指令）、场景 ID、物体清单、开始/结束时间、成功/失败标记 |

**采集时的硬性约束**（事后无法补救）：

- 所有流时间同步误差 < 10ms（同一时钟源或 PTP）
- 控制频率稳定（如 30/50Hz），掉帧自动丢弃该 episode
- 记录**原始未滤波数据**，滤波/插值留给处理环节（可复现）
- 失败 episode 也保留并打标签（对价值函数/恢复行为训练有用）

### 1.2 仿真采集（Isaac Sim）

仿真数据"便宜"，质检重心不在采集质量而在**生成配置的可追溯性**：

- 每条轨迹记录完整生成配置：场景种子、域随机化参数（光照/材质/摩擦/质量）、物体模型版本、任务初始化分布
- 配置即元数据，保证可复现、可按维度切片分析

## 2. 数据处理管线

### 2.1 完整性校验（自动门禁，第一道筛子）

- 各流长度是否一致、有无大段缺失
- 时间戳是否单调递增、有无乱序
- 文件可读、格式合规
- 不通过的直接进隔离区，不进管线

### 2.2 时间对齐与重采样

- 多流传感器频率不同（相机 30Hz、关节 500Hz、动作 50Hz），统一重采样到训练频率
- 插值方法要记录（线性/最近邻），动作标签与观测的滞后关系要校准（动作延迟标定）

### 2.3 信号清洗

- 关节速度/力矩异常尖峰检测（传感器故障）
- 图像黑帧/过曝/模糊检测
- 遥操作死区、误触发段检测

### 2.4 轨迹质量过滤

核心环节，见第 3 节指标。

### 2.5 切片与标注

- 长 episode 切成原子技能段（pick / place / open），或保留整段给端到端
- 语言指令标注：原子任务描述、子任务分解；标注一致性靠**双人标注 + 仲裁**或模板化生成
- 打成功/失败、质量等级标签

### 2.6 格式转换与入库

- 统一格式（LeRobot / RLDS / ARIO），一个事实来源（single source of truth）
- 原始数据不可变存储（raw zone），处理后数据带版本号（processed zone）

## 3. 数据质量评估：什么算"好数据"

四个层级，层层递进。

### 层级一：信号级质量（机器可自动判，硬性门槛）

| 指标 | 标准参考 |
|---|---|
| 时间同步误差 | < 10ms |
| 丢帧率 | < 0.1%，且不允许连续丢帧 |
| 控制频率稳定性 | 频率抖动 std 小，无大段降频 |
| 传感器异常 | 无 NaN/尖峰/黑帧/卡死帧 |
| 关节限位/超速违反 | 0 次（违反说明采集脚本有 bug 或碰撞） |

此层不合格 → 直接丢弃。

### 层级二：轨迹级质量（动作"干不干净"）

真机遥操作数据的关键指标：

| 指标 | 说明 |
|---|---|
| **轨迹平滑度** | jerk（加速度的导数）统计，过大说明操作员手抖/设备延迟大 |
| **无效停顿占比** | 静止超过阈值的时间占比；大量停顿 = 操作员犹豫/设备卡顿 |
| **回退/重复动作次数** | 抓了放、放了抓，说明犹豫或失败重试，污染动作标签 |
| **任务完成时长分布** | 同任务时长的离群点（过长）重点复查 |
| **碰撞/危险事件** | 力矩突增 + 非预期接触，需人工复核 |
| **主从延迟**（遥操作） | 主端指令到从端执行的滞后，延迟大的轨迹会让模型学到"犹豫" |

仿真数据对应指标：

- 物理合理性：无穿透、无爆炸力、接触力曲线连续
- 求解器稳定性：无物理引擎报错/重启

### 层级三：内容级质量（这条数据"教了什么"）

| 维度 | 评判方法 |
|---|---|
| **任务成功性** | 自动判定（目标状态检测）+ 人工抽检（抽检率 ≥5%） |
| **语言指令-行为一致性** | 指令说"拿红杯子"，轨迹是否真的拿了红杯子；VLM 自动初筛 + 人工复核 |
| **演示效率** | 轨迹长度 vs 该任务最优长度比值；过于冗余的演示会教出拖沓策略 |
| **动作习惯一致性** | 不同操作员风格差异（抓取姿态偏好等），元数据可追溯，必要时按操作员分桶评估 |

### 层级四：数据集级质量（这批数据"够不够好"）

单条数据完美不代表数据集好。数据集层面看三点：

**a) 覆盖度（Coverage）**——建任务×场景×物体×初始条件的覆盖矩阵：

```
任务: 抓取杯子
  ├─ 场景: 桌面/货架/水槽 × 光照: 亮/暗/侧光
  ├─ 物体: 5种杯子 × 位置分布(左/中/右/远/近) × 姿态(正/倒/斜)
  └─ 初始状态: 机械臂初始位姿分布
```

- 用直方图/热力图检查每个格子是否为空
- **空洞就是模型将来的失败点**——这是反向优化采集的最重要依据

**b) 多样性（Diversity）**

- 轨迹嵌入（视频 encoder 或状态序列编码）→ 聚类 → 看簇覆盖和均匀度
- 近重复检测：embedding 距离过近的轨迹去重（遥操作常见"量产垃圾"——同一轨迹无脑刷 100 条，对训练增益≈1 条）
- **经验法则：100 条多样轨迹 >> 1000 条雷同轨迹**

**c) 真机/仿真配比与 gap**（混合训练时）

- 渲染真实度：仿真帧 vs 真机帧做 FID/特征距离
- 域随机化覆盖：随机化参数的采样分布是否覆盖真机参数的实测范围（光照、摩擦系数、相机内外参误差）
- 终极测试：纯仿真数据训的策略真机成功率（sim2real gap 的直接度量）

### 层级五（终极裁判）：闭环训练验证

一切代理指标都不如直接验证：

1. **小规模冒烟测试**：新批次数据混入基线数据集，训一个小模型，对比任务成功率是否提升/不退化
2. **留一法（leave-one-batch-out）**：去掉某批次训练，看掉多少点，量化该批次的边际价值
3. **Scaling 曲线**：数据量 vs 成功率曲线，判断是否到边际收益递减点——加数据不涨点时先查数据质量再查模型

**建议把"每批次数据的边际成功率贡献"作为采集团队的 KPI**，而不是"采了多少条"。

## 4. 数据资产化：版本与溯源

- **数据版本管理**：类 git 的数据版本（DVC / 自研元数据库），每次训练实验记录用了哪些数据版本 → 可复现
- **Episode 级溯源**：任何一条训练数据能反查到：谁采的、哪台设备、什么配置、质检分数、被哪些实验用过
- **质量分沉淀**：每条 episode 带一个持续更新的质量档案（自动质检分 + 人工复核 + 训练贡献反馈）

## 5. 模型训练验证：数据质量的"背书"体系

### 5.1 背书的底层逻辑

数据质量无法自证，必须借助对照实验：

> 同一个模型 + 同一套训练配方（recipe），只换数据 → 性能差异 = 数据价值差异

背书的本质不是用了多强的模型，而是：

1. **用社区公认的模型和配方**（别人可复现）
2. **和公认基线数据做头对头对比**（同规模 vs Open X-Embodiment / DROID 子集）
3. **评测协议透明**（任务集、trial 数、成功率可审计）

模型只是测量工具，选型第一原则是**社区认可度**，第二是**对数据质量敏感**。

### 5.2 模型选型：两层架构

**第一层：轻量基线策略（内部快速迭代用）**

| 模型 | 规模 | 训练成本 | 特点 |
|---|---|---|---|
| **Diffusion Policy** | 100~500M | 单卡 4090/A100，1-2 天 | 当前 visuomotor 策略的事实标准基线，扩散生成动作 chunk |
| **ACT** | ~80M | 单卡数小时 | ALOHA/LeRobot 标配，CVAE + action chunking，训练极快 |

轻量模型是质检主力的原因：

- 迭代快：新到一批数据，当天就能出结果
- 对数据质量**极其敏感**：ACT 对遥操作数据的平滑度、一致性敏感——数据脏，成功率立刻崩；Diffusion Policy 对多模态分布建模好，数据里操作员犹豫、回退会明显拉低性能
- 它们是"数据质量的显微镜"，VLA 大模型因预训练知识太强，反而会掩盖数据问题
- LeRobot 对两者均有现成实现，格式即管线

**第二层：开源 VLA 基础模型（对外背书用）**

| 模型 | 机构 | 背书价值 |
|---|---|---|
| **π0 / π0.5** | Physical Intelligence | **当前最有说服力**：公认最强开源 VLA，"我们的数据微调 π0 达到 X% 成功率"是业内最硬的话术 |
| **OpenVLA (7B)** | Stanford | 学术引用最多的基线，论文对比标配 |
| **Octo** | Berkeley | 93M 较小，微调便宜，适合中等规模验证 |
| **GR00T N** | NVIDIA | 生态偏 NVIDIA/Isaac 时顺理成章 |
| **RDT-1B** | 清华 | 双臂场景选它 |

选型建议：**对外主打 π0（或硬件匹配的 GR00T/RDT），对内迭代用 Diffusion Policy + ACT**。

### 5.3 数据进模型前的关键决策

决定结果可比性，必须在报告里写死：

**a) 观测空间**

- 相机视角：几个视角、分辨率（224×224 是 VLA 标配；Diffusion Policy 可用更低）
- 本体状态：关节角 vs 末端位姿，二选一保持一致

**b) 动作空间**（最容易踩坑）

- **绝对 vs 增量（delta）**：VLA 多用绝对 EE 位姿；delta 更平滑但累积误差
- **关节空间 vs 任务空间（EE）**：跨本体泛化用 EE，单本体精度用关节
- **action chunking**：一次预测未来 k 步（DP 常 16，ACT 常 50-100），推理时只执行前 m 步
- **归一化**：按数据集统计量逐维度 z-score 或 min-max 到 [-1,1]；**统计量必须按本数据集重算并随 checkpoint 保存**，换数据不重算会静默掉点

**c) 频率对齐**：训练频率（如 10Hz 动作）与采集频率的重采样方式固定

### 5.4 轻量基线训练要点（Diffusion Policy 为例）

```
- 图像编码器：ResNet18 从头训（不要冻结预训练，视觉分布差异大）
- 扩散头：DDPM 100 步训练 / DDIM 10 步推理
- 观测窗口：2 帧历史；动作 chunk：16 步
- Batch 256，AdamW lr 1e-4，训练 ~500 epoch 或至验证成功率收敛
- 单卡 4090 大约 1-2 天（50-100 条演示量级）
```

关键经验：

- **checkpoint 按 rollout 成功率选，不按 loss 选**——扩散 loss 和任务成功率相关性很弱，新手最常犯的错
- 训多个 seed（≥3），报均值±std，单 seed 的数字不可信

### 5.5 VLA 微调要点（π0 为例）

- 用官方 openpi / LeRobot 管线，数据转 LeRobot 格式
- 微调方式：**LoRA**（单卡~8 卡可行，快）vs **全量微调**（效果上限高，8×A100/H100 级）
- 数据配比：你的数据单训 vs 与 OXE 公开数据**共训（co-training）**——共训防止小数据过拟合，也是和公开数据"同台竞技"的公平设置
- 记录官方 normalization stats 重算、action 维度映射（本体自由度 → 模型 action 空间 padding）

### 5.6 评估协议（数字可信度全在这）

**仿真评测**（便宜、可复现，用于初筛和对外佐证）：

- **SimplerEnv**：专门模拟真实机器人评测环境，与真机结果相关性被验证过，社区认可度高
- **LIBERO**（lifelong 操作基准）、**ManiSkill**（操作任务套件）
- 每个任务 ≥100 次 rollout，不同初始状态采样

**真机评测**（最终背书，必须做）：

- 固定任务套件：10-20 个任务，覆盖**已见场景 / 未见物体 / 未见干扰**三档
- 每任务 10-20 trials，初始位姿随机化但种子公开
- **评测人与训练数据版本隔离**（评的人不知道用的是哪版数据，避免无意识偏袒）
- 报成功率 + 分任务明细 + 失败模式分类

### 5.7 背书的呈现形式（怎么让别人信）

按说服力从强到弱：

1. **头对头对比**（最有力）：同配方下，你的数据 vs 同规模公开数据（DROID/OXE 子集）微调同一模型 → 成功率对比表
2. **Scaling 曲线**：1x / 2x / 4x 数据量的成功率曲线——健康曲线（持续上升）本身证明数据多样、无大量冗余
3. **留一法消融**：去掉某批次数据掉多少点 → 每批次的边际价值量化
4. **Datasheet**：随数据发布覆盖矩阵、质检统计、训练配方、评测协议——透明度本身就是背书
5. 开源模型权重 + 评测脚本，让别人自己复现

### 5.8 算力与节奏估算

| 环节 | 硬件 | 周期 |
|---|---|---|
| Diffusion Policy / ACT 基线 | 1× 4090/A100 | 每批数据 1-2 天 |
| π0 LoRA 微调 | 1-4× A100 | 2-3 天 |
| π0 全量微调 | 8× A100/H100 | ~1 周 |
| 真机评测（20 任务×15 次） | 1 台机器人 | 2-3 天/轮 |

建议节奏：**每批新数据 → 当周跑 ACT/DP 冒烟（内部门禁）→ 每季度跑一次 VLA 全量对比（对外背书更新）**。

注意：轻量基线（ACT/DP）才是日常数据飞轮的主力工具，VLA 背书一年做几次就够——别反过来，否则迭代成本会拖死飞轮。

## 6. 数据评测详解

三种评测手段回答三个不同的问题，是串联的漏斗，不是并列选项。越贵的手段用在越少、越确定的数据上。

| 手段 | 回答的问题 | 成本 | 频率 |
|---|---|---|---|
| **离线质检**（不训模型） | 数据本身有没有硬伤？干不干净？ | 低 | 每批数据必做 |
| **轻量基线评测**（ACT/DP） | 这批数据能不能教出策略？相对上批变好没？ | 中 | 每周/每批 |
| **VLA 微调评测** | 这批数据在业内标尺下值多少？（对外背书） | 高 | 每季度/发布前 |

### 6.1 采集数据的离线评测（不训模型）

#### a) 自动化质检：实现级细节

**平滑度（jerk）**

```python
# 对关节位置 q(t)，采样周期 dt
jerk = np.diff(q, n=3) / dt**3           # 三阶差分
score = np.percentile(np.abs(jerk), 95)  # 用 95 分位数，抗离群点
```

- 同任务、同设备先跑 50 条"公认好"的数据建立基线分布，新数据超过基线均值 + 2σ → 打标复查
- 阈值不要拍脑袋，从自己的好数据里统计出来

**无效停顿检测**

```python
vel_norm = np.linalg.norm(np.diff(q, axis=0), axis=1)
is_static = vel_norm < (0.01 * np.percentile(vel_norm, 95))
# 连续静止段 > 2s 且夹爪/目标物体都不动 → 记为无效停顿
```

- 注意区分"合理停顿"（对准、等待物体稳定）和"犹豫停顿"

**回退/重复动作检测**

- 把 EE 轨迹离散到网格（如 2cm 格子），统计同一格子被访问 ≥3 次（方向不同）的片段
- 或检测夹爪"开→关→开"的短周期切换（< 1s 内反复）——典型的抓了放

**主从延迟估计（遥操作）**

- 对主端指令序列和从端实际位置做互相关（cross-correlation），峰值偏移量即延迟
- 延迟 > 100ms 的轨迹建议降权或剔除——模型会学到"指令后等待"的坏习惯

**时长离群检测**

- 按任务分组，IQR 法则：超过 Q3 + 1.5×IQR → 复查
- 过长通常意味着犹豫/失败重试没被标记

#### b) 人工评审：怎么抽、怎么评

自动化只能抓硬伤，语义层要靠人，但人必须用得省。

**抽样策略（不是随机抽）**：

- 5% 随机抽检（监控整体质量水位）
- + 100% 自动质检打标的（机器说可疑的人全看）
- + 100% 新任务/新操作员的前 20 条（新来源风险最高）

**评审 rubric（打分表要具体）**：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 任务完成度 | 未完成 | 完成但勉强 | 干净完成 |
| 动作意图清晰 | 多次犹豫回退 | 少量犹豫 | 一气呵成 |
| 与指令一致 | 做错了 | 部分对 | 完全对 |

- 双人评审，计算 **Cohen's kappa 一致性系数**（< 0.6 说明 rubric 定义模糊，先改 rubric 别怪评审员）
- 评审结果回写 episode 质量档案，喂给操作员排名

#### c) 数据集级统计评测

**覆盖矩阵**：任务、场景、物体、初始位姿离散化后做笛卡尔积计数，画热力图。落地技巧：

- 初始位姿/物体位置的连续量做网格化（如桌面划 5×5 格）
- 空格 = 明确缺口；某格数据量 > 均值 3 倍 = 冗余

**多样性**：

```python
# 用预训练视频 encoder（如 R3M、VC-1）提每帧特征，轨迹取均值池化
emb = encoder(frames).mean(axis=0)   # 每条约 512 维
# 1) 近重复检测：余弦相似度 > 0.95 的轨迹对 → 只留一条
# 2) 覆盖监测：对已有数据集 embedding 做 k-means(如 k=100)，
#    看新数据落入各簇的增量——新数据全落在旧簇 = 多样性停滞
```

### 6.2 轻量基线模型评测（核心日常手段）

#### a) 对照实验设计

评测数据 = 做对照实验，必须锁死的变量：

```
固定：模型架构 + 超参 + 训练步数 + 观测/动作空间 + 归一化方式 + 评测任务集 + 种子数
变量：只有数据
```

两种实验：

- **增量实验（新批次验收）**：baseline = 旧数据集 D 训的模型；实验组 = D + 新批次 ΔD。成功率不降且目标任务有提升 → ΔD 入库
- **替代实验（数据价值横评）**：同规模下你的数据 vs 公开数据（DROID 子集采样到同样条数），数字可直接写进对外材料

注意训练预算要对齐：比较"100 条你的数据 vs 100 条公开数据"才公平；训练步数也按数据量等比设置（或都训到收敛），否则比较的是训练时长不是数据。

#### b) 评测指标与统计显著性

**主指标：rollout 成功率**，统计坑很深：

- 成功率是二项分布，置信区间 = p ± 1.96×√(p(1-p)/n)
- n=20、p=0.5 时，95% CI 宽达 **±22%**——20 次 rollout 说"提升了 10%"在统计上是噪声
- 实用标准：每任务 **≥50 trials**，或报 Wilson 区间；要检测 10% 的差异，每任务需 ~100 trials
- 所以：仿真里跑 100+ 次（便宜），真机评测靠多任务聚合（20 任务 × 10 次 = 200 trials 整体对比）

**辅助诊断指标**（从训练过程读数据问题，不花 rollout 成本）：

| 信号 | 指向的数据问题 |
|---|---|
| 验证集动作预测误差**高且均匀** | 数据本身噪声大/操作员风格不一致 |
| 训练误差低、验证误差高 | 数据多样性不足（过拟合到雷同轨迹） |
| 误差在某些动作维度（如旋转、夹爪）显著高 | 该维度标注/采集有系统性问题 |
| loss 很快收敛到平台期 | 数据量或多样性到瓶颈 |

不跑真机就能定位数据问题类型，直接指导下一轮采集方向。

#### c) 失败分析结构化

rollout 失败的 case 不许只记"失败"，要归因分类：

```
失败归因 taxonomy：
├─ 感知失败：找错物体/被干扰物骗 → 补对应场景的干扰数据
├─ 接近失败：到了但抓取姿态不对 → 补该物体不同姿态的演示
├─ 执行失败：抓到了但滑落 → 可能是力控/夹爪数据问题
├─ 长程失败：中途卡住不动 → 数据里恢复行为缺失
└─ 指令失败：做对动作但搞错目标 → 语言标注问题
```

每一类直接映射到一种采集动作——这就是飞轮转动的具体机制。

#### d) 仿真评测的角色

轻量基线 + 仿真评测 = 零真机成本的日常迭代：

- 在 Isaac Sim 里建固定评测场景集（对应真机任务）
- 每批数据自动跑 100+ rollout，出趋势图
- **但要定期校准**：每季度跑一次真机评测，验证仿真成功率与真机成功率的相关性（仿真涨真机不涨 = 仿真评测场景过拟合，要更新）

### 6.3 VLA 训练后评测 & "VLA 是必做题吗"

#### a) 直接回答：不是必做题，分场景

| 目的 | 需要做到哪层 |
|---|---|
| 内部优化采集（飞轮） | **不需要 VLA**。轻量基线 + 离线质检完全够用 |
| 对合作方/客户证明数据可用 | **不一定**。Datasheet + 轻量基线头对头对比 + 透明评测协议，已比业内大多数数据供应商严谨 |
| 对外建立行业声誉/卖数据/发论文 | **需要做**。社区现在的"硬通货"就是 π0/OpenVLA 微调后的成功率对比 |

**VLA 是背书的上限，不是背书的前提。** 且有一个重要事实：

> VLA 的强预训练会"兜底"数据缺陷——中等质量数据微调 π0 也能得到不错的成功率，区分度反而不如轻量模型。**轻量基线对数据质量更敏感（适合内部裁判），VLA 对数据质量更宽容（适合对外展示）**，两者角色不同，不矛盾。

#### b) 决定做 VLA 评测时的协议要点

**三种训练设置，各回答一个问题**：

| 设置 | 回答的问题 |
|---|---|
| 只用你的数据微调 | 数据独立可用性（能不能自成体系） |
| 你的数据 + OXE 共训 | 数据在混合池中的兼容性与增量价值 |
| OXE 基线 vs OXE+你的数据 | **增量价值**（最有说服力的对比） |

**评测任务必须分层**：

- 已见任务已见场景（数据内分布）
- 已见任务未见物体/场景（泛化）
- 全新任务（语言指令组合泛化）
- 只报第一档是刷分，三档全报才是背书

**和基线公平对比**：

- 用官方 recipe、官方推荐的微调超参，只换数据
- 数据规模对齐（条数或小时数对齐，并在报告里注明用的是哪种）
- 报官方 benchmark 数字（LIBERO/SimplerEnv）+ 真机数字

#### c) 成本控制的现实路径

1. 先 **LoRA 微调 π0**（1-4 卡，2-3 天）拿一版数字，验证流程跑通
2. 只在数据有重大版本更新时才跑全量微调
3. 真机评测任务集从轻量基线的任务集里**继承子集**（复用评测基建，别另起炉灶）

### 6.4 评测节奏一页纸

```
每批数据：
  离线自动质检（硬伤过滤）→ 人工抽检 5% → 覆盖矩阵更新
        ↓ 通过
  ACT/DP 冒烟训练（1-2天）→ 仿真 rollout 100+ 次
        ↓ 成功率不降
  入库 + 失败归因 → 采集任务单
        ↓ 每季度/重大版本
  π0 微调（LoRA起步）→ 分层评测 → 对外背书材料更新
```

评测的灵魂两句话：**轻量模型当裁判天天用，VLA 当招牌偶尔用；所有对比实验，锁住一切只动数据。**

### 6.5 模型输出解析与三层验证

#### a) ACT / DP 的输出：动作 chunk

输入「多视角图像 + 本体状态」，输出**未来 k 步的动作向量序列**：

```
输出 shape: (k, action_dim)
例如 k=16（DP）或 k=50（ACT），action_dim 取决于动作空间设计：

单臂 EE 空间（常用）：
  [Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper]  → 7 维
  或绝对 EE 位姿 [x,y,z,qx,qy,qz,qw, gripper]  → 8 维
单臂关节空间：
  [joint1...joint6, gripper]  → 7 维
双臂（ALOHA 类）：
  [左臂6关节, 左夹爪, 右臂6关节, 右夹爪]  → 14 维
```

每一行是"未来第 t 步机器人应到达的目标位姿/关节角 + 夹爪开合度"，归一化到 [-1,1]（推理时用保存的统计量反归一化）。

| | ACT | Diffusion Policy |
|---|---|---|
| 机制 | CVAE 一次性回归出整个 chunk | 从纯噪声迭代去噪（推理 ~10 步 DDIM）生成 chunk |
| 输出特性 | 确定性较高，单次前向 | 每次采样不同（**多模态**：同一画面可生成多种合法动作） |

执行方式：receding horizon——每步（或每 m 步）重新预测 chunk，只执行前 m 步（m < k）再重新观测；ACT 常用 temporal ensemble（多个历史 chunk 预测按指数加权平均）。

#### b) π0.5（VLA）的输出：同样是动作 chunk，但带语言

```
输入: 多视角图像 + 语言指令 + 本体状态
         ↓ VLM 主干（System 2）→ Action Expert（扩散/流匹配头，System 1）
输出: 动作 chunk (50, action_dim)  ← 和 DP 本质相同
```

- π0 默认一次预测 50 步，action_dim padding 到 32 维以兼容各种本体
- 与 ACT/DP 的本质差异：多了语言条件（开放词汇指令），泛化来自互联网预训练 + 微调数据；π0.5 还可先输出**子任务文本**（latent subtask）再生成动作，该中间文本可检查

#### c) 三层验证

**第 1 层：开环验证（open-loop，不接触机器人）**——用留出验证集，模型预测 vs 真人演示：

| 指标 | 说明 |
|---|---|
| **动作预测误差** | MSE/L1（反归一化后按维度报），夹爪和旋转维度最有诊断价值 |
| **分步误差曲线** | 误差随预测步数 t=1..k 的增长；健康=缓慢增长，第一步就大=对齐/延迟问题，爆炸=训练发散 |
| **chunk 平滑度** | 输出 chunk 内部 jerk |
| **多模态合理性**（DP/π0） | 同一观测采样 N 次看分布：演示有多种做法时应分叉，演示一致时分叉 = 没学好 |

**警告：开环误差低 ≠ 闭环性能好**（误差累积/compounding error：模型偏离演示分布后误差滚雪球）。开环验证只用于训练监控、checkpoint 粗筛、数据问题诊断。

**第 2 层：仿真闭环**——模型接 Isaac Sim 闭环跑：

```
loop:
    obs = sim.get_obs()                    # 渲染图像 + 关节状态
    chunk = model(obs, instruction)        # (k, action_dim)
    sim.execute(chunk[:m])                 # 只执行前 m 步
```

- 每任务 ≥100 次 rollout，初始状态随机化（种子固定可复现）
- 报成功率 + 分任务明细 + 失败录像归档

**第 3 层：真机闭环（最终裁判）**——同 6.2/6.3 节协议。额外验证工程指标：

- **推理延迟**：模型前向耗时 < 控制周期（如 50ms），否则动作滞后（π0 级模型需 A100/4090 级 GPU 实时推理）
- **动作执行平滑性**：chunk 衔接处有无跳变（temporal ensemble 是否生效）
- **安全边界**：输出是否曾超工作空间/速度限制（后处理 clip 触发率）

**VLA 特有验证项**：

| 验证项 | 方法 |
|---|---|
| **语言跟随** | 同一画面换指令（"拿红杯"/"拿蓝杯"），动作目标应切换；不切换 = 模型忽略语言只记视觉 |
| **指令泛化** | 同义改写指令，成功率是否保持 |
| **未见任务** | 训练集没有的任务组合，验证零样本泛化（VLA 核心卖点，必须测） |
| **子任务分解**（π0.5） | 检查输出的中间子任务文本是否合理（VLA 可解释性的独特入口） |

要点：**输出端 ACT/DP/VLA 是同质的（都是动作序列），验证管线可以完全复用**——ACT/DP 的评测基建跑 π0.5 时只需加语言相关测试项。

### 6.6 部署一致性审计与跨本体兼容

#### a) 核心原则：不需要"逐条一致"，需要"分布一致"

策略只在训练数据的分布内有效；评测时机器人设置可以变，但必须变在训练数据覆盖过的范围内。

| 设置 | 要求 | 原因 |
|---|---|---|
| **相机位姿/内外参** | **严格一致**（或训练时覆盖多个机位） | 视觉策略对相机极敏感，相机挪 10cm、俯仰角差几度，图像分布就变，成功率可能直接归零 |
| **动作空间语义** | **严格一致** | 输出向量每一维的含义（坐标系、关节顺序、夹爪 0/1 定义）训练和执行必须同一套 |
| **控制频率** | 一致 | 数据里相邻动作间隔 33ms，按 10Hz 执行 = 整个动作节奏错（等效快放/慢放） |
| **机械臂本体** | 一致（见跨本体节） | 动作维度、工作空间、动力学绑定本体 |
| **初始位姿/物体位置** | **不要一致，要同分布随机化** | 见下 |

#### b) 初始状态：恰恰不应该"补一致"

评测时把机械臂每次 reset 到训练集里同一个初始位姿，是常见错误——测出的是"模型记住这条轨迹没有"，不是"模型会干活没有"。

- 训练采集时初始位姿/物体位置就应有目的地**在一个范围内采样**（如桌面 30×30cm 随机放）
- 评测时在**同一范围内随机采样**，种子固定保证可复现
- 评测初始状态超出训练覆盖范围 = OOD，失败不怪模型，是采集没覆盖（回到覆盖矩阵）
- 判断标准：不是"设置一不一样"，而是"评测状态的每个维度是否落在训练分布的覆盖格子里"

#### c) 设置不一致了怎么补（按代价从小到大）

1. **采集时留冗余**（最便宜）：相机机位故意设 2-3 个、初始位姿主动扫范围
2. **标定对齐**：换场地后重做相机外参/基座标定，把坐标系变换回来（前提是 EE 空间动作且几何可对齐）
3. **数据增广/域随机化**：仿真侧随机化相机位姿、光照、纹理，让策略对机位鲁棒
4. **补采数据**：评测场景超出训练分布 → 定向补采（飞轮正常动作）
5. **重训**（最贵）：动作空间语义、控制频率等根本性不一致，只能改管线重训

一句话：**几何不一致靠标定补，分布不一致靠补采补，语义不一致补不了只能重训。**

#### d) 不同机械臂型号的兼容性

**ACT / DP：基本不兼容**

- 动作空间绑定具体本体（关节维度、工作空间、限位），换臂 = 模型直接不可用
- 唯一例外：两臂运动学高度相似（同为 6 自由度、工作空间接近）且动作用 EE 空间表示——可通过各臂 IK 解算迁移，但动力学差异仍会掉点

**VLA（π0.5 等）：为跨本体设计**

- 通用 32 维动作空间（padding），预训练混了几十种机器人数据（OXE）
- 换本体做法：采 50-100 条新本体演示 → 微调 → 模型自动学会该本体动作映射
- 注意：**微调后模型仍绑定微调用的本体**。VLA 解决的是"不用从零训练"，不是"一个权重通吃所有臂"

**实操结论**：

| 场景 | 方案 |
|---|---|
| 同型号臂、换场地/换相机 | 标定对齐 + 补采少量新场景数据微调 |
| 换不同型号臂 | EE 空间动作 + IK 重定向可部分迁移；常规做法是新臂重新采集 + 微调（VLA 路线成本可接受） |
| 多臂混采训练 | 元数据必须带本体 ID，action padding 对齐；ACT/DP 建议一臂一模 |

**评测环境搭建第一步不是搭场景，而是做"训练分布 vs 评测设置"一致性审计**——相机标定参数、坐标系定义、控制频率、初始状态采样范围，逐项对齐确认，作为评测协议 checklist 的一部分。

## 7. 反向优化采集：闭环怎么转起来

这是"飞轮"区别于"流水线"的地方。反馈信号来自三处：

### 7.1 模型失败分析 → 采集补缺（主循环）

```
部署/评测失败的 case
  → 归因：是没见过这种状态（覆盖空洞）？
          还是见过但演示不一致（标注/质量问题）？
          还是动作本身超出数据分布（需要新技能）？
  → 生成补采任务单：明确要补的场景/物体/初始状态/失败模式
  → 定向采集（不是随机多采）
```

实操：维护一个**失败 case 库**，每周评审，转成采集任务。仿真侧同理：真机失败的场景，在 Isaac Sim 里重建并批量生成变体。

### 7.2 覆盖矩阵空洞 → 采集计划

- 每月对覆盖矩阵做一次审计，空洞格子排优先级进采集计划
- 多样性指标停滞（新数据 embedding 都落在已有簇里）→ 该换场景/物体/操作员了

### 7.3 质检数据 → 操作员与设备优化

- 操作员维度：每个人的无效停顿率、平滑度、成功率排名 → 针对性培训，淘汰持续低质量操作员
- 设备维度：某台臂的延迟/抖动异常 → 检修或标定
- 流程维度：某类任务废品率普遍高 → 可能是任务设计/遥操作界面问题，改采集工具而非怪操作员

### 7.4 仿真 ↔ 真机互哺

- 真机失败场景 → 仿真复现 → 生成 N 个变体 → 训练 → 回真机验证
- 仿真训练的盲点（域随机化没覆盖到的真实参数）→ 通过真机残差（real-vs-sim 轨迹偏差）识别 → 调整随机化范围

## 8. 落地优先级建议

资源有限时按此顺序建：

1. **先建元数据和溯源**（采集时多存字段，成本最低收益最大）
2. **自动信号级质检**（挡住垃圾数据）
3. **覆盖矩阵 + 失败 case 库**（飞轮的转向盘）
4. **闭环训练验证流程**（每批次数据训一版模型看效果）
5. 最后才是精细化的轨迹级/多样性指标

常见反模式：

- ❌ 用"采了多少小时/多少条"考核采集团队 → 必然刷出大量雷同垃圾数据
- ❌ 质检全靠人看回放 → 规模化后不可行，人只该做抽检和仲裁
- ❌ 处理过程改原始数据不留版本 → 出了问题无法回溯
- ❌ 仿真数据不做 sim2real 验证就大规模混训 → 可能引入系统性偏差
- ❌ 按 loss 选 checkpoint → 扩散策略 loss 与成功率弱相关，必须按 rollout 成功率选
