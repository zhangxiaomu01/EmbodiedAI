# 具身数据团队定位与影响力策略

面向 15 人规模具身数据团队的方向选择：如何让"小批量数据"产生业内影响力，以及在产出与预算之间取得平衡。

## 一、先做一次现实校准

规模赛道已经关闭：

| 公开数据集 | 规模 |
|---|---|
| Open X-Embodiment | 100 万+ 轨迹，22 种本体 |
| DROID | 7.6 万条轨迹 / 约 350 小时 |
| BridgeData V2 | 约 6 万条 |

15 人团队采 1 万条，在"训练大模型"这条价值链上几乎不可见。**所以不要把自己定位成"数据供应商"**——那个位置已被大厂占死。

但业内真正缺的不是数据量，是这三样：

1. **稀缺赛道的数据**（大厂没覆盖的细分）
2. **"好数据"的评判标准**（谁定义标准，谁有话语权）
3. **小数据如何发挥大价值的方法论**（配比、域随机化、sim2real 迁移）

这三样，15 个人做得动，而且没有规模壁垒。

## 二、数据价值公式（替代"条数"的决策依据）

```
数据价值 = 稀缺性 × 规范性 × 可验证性 × 可复用性
```

- **稀缺性**：别人没有的本体/任务/模态。1000 条烂大街的单臂抓取 = 0；300 条双臂长程协调 = 高
- **规范性**：格式、元数据、质检分、datasheet 齐全 → 别人才敢用
- **可验证性**：附基线模型结果 + 评测协议 → 价值可被证明
- **可复用性**：工具链开箱即跑 → 降低别人接入成本

按这个公式，团队现有资产其实是**同时掌握真机采集和 Isaac Sim 仿真两侧**——这是纯学术组和纯数据公司都不完整具备的。

## 三、可增加业内影响力的六种生产方式（按性价比排序）

| 方式 | 人力 | 预算 | 影响力 | 说明 |
|---|---|---|---|---|
| **① 评测基准 + 公开榜单** | 2-3 | 中 | **最高** | 提出 10-20 个真机/仿真任务集 + 评测脚本 + 固定种子协议，邀请外部团队来跑分。别人引用你、来你这里测评 = 天然行业节点 |
| **② 数据质量工具包开源** | 1-2 | **极低** | 高 | 把数据飞轮的质检实现成工具（jerk/停顿/回退检测、覆盖矩阵可视化、质量档案 schema、datasheet 模板）。**定义别人怎么评数据**，比多采一万条更有话语权 |
| **③ 垂直赛道标杆数据集** | 4-5 | 中 | 高 | 选 1-2 个空白赛道，300-800 条做到极致质量 + 完整质检报告 + 基线对比，作为首个 release |
| **④ sim-real 配对数据 + 消融研究** | 3 | 中 | 高 | 同场景同任务的"仿真-真机配对数据"，做"纯仿真/纯真机/不同配比"的系统性消融，产出可发表的方法论结论。**这是独有壁垒**，大厂不方便做这种诚实对比 |
| **⑤ 失败与恢复数据** | 2 | 低 | 中高 | 公开数据集几乎全是成功演示，失败+恢复是稀缺资产，做价值函数/恢复策略的人极需要 |
| **⑥ 与本体厂商合作"官方数据"** | 1 | 低 | 中 | 借本体厂商渠道分发，成为"XX 臂官方教程数据集"，用别人的流量 |

**建议组合**：①+②+③+④ 为核心，⑤做差异化补充，⑥做渠道。共同特点——**不靠条数取胜，靠"标准 + 场景 + 方法论"取胜**。

### 3.1 ① 评测基准 + 公开榜单

#### 核心逻辑

大家各自在私有任务上报成功率，数字不可互比。一旦有一方提供"可比性"——同一套任务、同一套初始状态分布、同一套判定标准——它就掌握了"定义裁判标准"的话语权。

#### 具体构成

| 组成部分 | 内容 |
|---|---|
| **任务集** | 10-20 个任务，每个定义：场景布局、物体清单、初始状态分布、成功判定条件 |
| **种子表** | 每个任务的评测种子固定并公开，保证可复现但不被提前知道 |
| **硬件规格书** | 本体型号、相机位姿/内参、夹爪、桌面尺寸——别人复现的最小要求 |
| **评测脚本** | rollout 自动化、成功判定、日志格式、结果汇总 |
| **协议文档** | trial 数、盲评规则、失败记录方式、统计口径（Wilson 区间） |

#### 双轨设计（关键）

```
仿真榜单：任何人下载即可跑，零门槛，用于参与量和引用
      ↓ 背书升级
真机榜单：需要硬件；或提供"提交模型包，我们代跑"服务 → 权威档
```

先做仿真榜单（成本低、可自助、可无限次），真机榜单作为权威档后置。这条路径与 SimplerEnv 被社区接受的方式一致。

#### 防作弊与防过拟合

- 初始状态由种子生成，种子表分批公布（评测时才给全）
- 判定代码不公开，只公开判定规则描述
- 模型提交在沙箱运行，禁止联网
- **任务集定期换代（v1/v2）**——公开太久必然被过拟合，换代本身就是话题

#### 起步与投入

| 项 | 说明 |
|---|---|
| 最小可行版 | 5 个仿真任务 + 1 个真机任务，脚本 + 协议文档可跑通 |
| 人力 | 2 人（1 评测工程 + 1 仿真场景） |
| 周期 | 6-8 周出 v0.1，之后 1 人持续运营 |
| 冷启动 | 主动邀请 3-5 家（高校实验室最愿意来跑）+ 自己先跑出榜 |

- **影响力证据**：参与团队数、被作为 baseline 引用、任务集被复用到别的论文
- **最大的坑**：任务太简单没人稀罕、太难没人愿跑；判定不能靠人工，否则失去公信力

### 3.2 ② 数据质量工具包开源

#### 核心逻辑

六个方向里成本最低、见效最快。现有生态（LeRobot 做数据处理、DROID 做采集规范）仍缺"统一的数据质量评分 + 覆盖度审计"工具。谁先做成标准件，谁就定义了行业怎么描述数据质量。

#### 具体模块（按优先级）

| 模块 | 功能 | 优先级 |
|---|---|---|
| **自动质检** | jerk、无效停顿、回退/重复、主从延迟、时长离群，输出 0-100 分 + 问题定位 | P0 |
| **覆盖矩阵** | 任务×场景×物体×初始位置热力图，直观显示空格 | P0 |
| **Datasheet 生成** | 从元数据自动生成标准数据卡（采集条件、质检统计、覆盖度） | P1 |
| **多样性分析** | 视频 encoder 嵌入 + 近重复检测 + 聚类覆盖 | P1 |
| **格式转换** | 各家本体数据 → LeRobot 统一格式 | P1 |

#### 产品形态

```
pip install <your-tool>
your-tool check    ./data        # 质检打分，输出 HTML 报告
your-tool coverage ./data        # 覆盖热力图
your-tool datasheet ./data       # 生成数据卡
```

- Python 包，CLI + API 双入口
- 报告输出 HTML（可分享、可截图传播）
- 阈值可配置，但提供"业界参考默认值"——默认值就是标准

#### 起步与投入

| 项 | 说明 |
|---|---|
| MVP | 3 个命令，能对 LeRobot 格式数据跑通 |
| 人力 | 1 人 6-8 周，之后 0.5 人维护 |
| 成本 | 几乎为零（无需硬件、无需算力） |
| 冷启动 | 在 LeRobot 社区、具身智能 Slack/Discord 发布 + 一篇技术博客 |

- **影响力证据**：pip 下载量、GitHub star、被别人 pipeline 集成、外部开发者 PR 数
- **最大的坑**：不要做"大而全的数据平台"；只做小而准的垂直工具，必须有真实 demo 数据能跑通

### 3.3 ③ 垂直赛道标杆数据集

#### 核心逻辑

不是"又一份操作数据"，而是"某个细分领域目前唯一可用的公开数据"。规模可以小，但必须是该赛道的**默认引用对象**。

#### 赛道选择的三条标准

| 标准 | 判断方法 |
|---|---|
| **稀缺** | 在 HuggingFace / OXE 检索：该任务+该模态基本没有公开数据 |
| **可采** | 现有硬件 + 场景就能做，不需要新买设备 |
| **有下游** | 有人在训这类任务（看论文、看开源项目 issue） |

#### 候选赛道（按稀缺度）

| 赛道 | 稀缺度 | 采集难度 | 备注 |
|---|---|---|---|
| 双臂协调长程任务 | 高 | 高 | 公开数据极少，研究需求大 |
| 可变形物体（布料/线缆/袋子） | 很高 | 高 | 几乎空白 |
| 透明/反光物体抓取 | 高 | 中 | 感知研究刚需 |
| 移动操作（mobile manipulation） | 高 | 高 | 需要底盘 |
| 精密插装（公差级） | 很高 | 很高 | 工业界需求 |
| 多操作员风格数据 | 中 | 低 | 研究偏好/风格时有用 |

#### 数据规模与质量的取舍

**300-800 条，每条极致质量**，具体标准：

- 2-3 个机位、完整元数据、质检分 ≥ 85
- 覆盖矩阵无大空洞（有意设计的边界情况除外）
- 全部 episode 可溯源（操作员、设备、配置）
- 成功/失败都保留并标注

配套交付物（缺一不可）：

1. Datasheet（用 ② 的工具生成）
2. 质检统计报告
3. ACT / DP 基线成功率
4. π0 LoRA 微调结果
5. 失败案例集与归因

#### 起步与投入

| 项 | 说明 |
|---|---|
| 人力 | 4-5 人（2 操作员 + 1 采集工程 + 1 数据 + 1 算法） |
| 周期 | Q1 跑通闭环 500 条，Q3 正式发布 v1 |
| 发布渠道 | HuggingFace Datasets（LeRobot 格式）+ 技术报告 |
| 冷启动 | 本体厂商渠道转发 + 论文引用 + 社区 demo 视频 |

- **影响力证据**：下载量、被 fine-tune 的公开报告、被论文作为对比数据
- **最大的坑**：**质量参差会毁掉信誉**。宁可 300 条全优，不要 1000 条混杂——数据发布是一次性信誉投资

### 3.4 ④ sim-real 配对数据 + 消融研究

#### 核心逻辑

这是真正的独有壁垒：**同时拥有真机采集和 Isaac Sim 生产能力**。纯学术组缺仿真规模，仿真厂商（NVIDIA）不方便做"仿真到底有多大用"的诚实对比，纯数据公司缺仿真。两边都有，才能回答所有人关心但没人敢公开回答的问题：

> 仿真数据到底能替代多少真机数据？什么配比最优？域随机化到底哪几个参数有用？

#### 配对数据的关键定义

同一个任务、同一个场景、**同一个初始状态**，真机和仿真各采一遍，且以下参数对齐：

| 对齐项 | 要求 |
|---|---|
| 场景几何 | 物体尺寸/位置/桌面布局从仿真导出，真机按同一坐标摆放 |
| 相机 | 同一型号、同一位姿，内外参标定后写入仿真 |
| 动作空间 | 同为 EE 空间，控制频率一致 |
| 初始状态 | 同一份种子表，真机按仿真导出的位姿复位 |
| 物体物理属性 | 实测质量/摩擦系数写入仿真（最容易忽略） |

前置验证：**sim-real 帧级对比**（FID / 特征距离 / 物体检测一致性），不达标先修场景，别急着做实验。

#### 消融矩阵

```
              ACT    DP    π0-LoRA
纯真机         ✓      ✓      ✓
纯仿真         ✓      ✓      ✓
真机:仿真 1:1   ✓      ✓      ✓
         1:3   ✓      ✓      ✓
         1:10  ✓      ✓      ✓
+域随机化      ✓      ✓      ✓
```

固定模型架构与超参，只动数据来源与配比，评测全部在**真机**上做（唯一有说服力的终点）。

#### 能产出的结论

1. **配比曲线**：真机数据占比 vs 真机成功率的拐点在哪
2. **域随机化的边际收益**：逐参数（光照/材质/摩擦/相机噪声）消融，哪个最值
3. **sim2real gap 分解**：视觉 gap vs 动力学 gap 各占多少（通过交叉实验拆分）
4. **小数据放大效应**：100 条真机 + N 条仿真能做到多少——这个数字对全行业都有参考价值

#### 起步与投入

| 项 | 说明 |
|---|---|
| 人力 | 1 仿真 + 1 采集 + 1 算法 |
| 周期 | 单任务配对采集 2-3 周；全矩阵实验 1-2 个月（算力按需租） |
| 成本 | 主要是真机时间 + LoRA 租卡，预算不高 |
| 产出 | 技术报告/论文 + 一套公开的配对数据（本身又是稀缺资产） |

- **影响力证据**：论文引用、被当作"仿真数据配比"经验参考、NVIDIA/学术界引用该诚实结论
- **最大的坑**：仿真重建保真度不够 → 结论不可信。必须先把帧级对齐做好

### 3.5 四个方向的依赖关系与推荐节奏

```
② 工具包 ──(提供质检 & datasheet)──┐
                                    ↓
③ 垂直数据集 ──(提供任务集)──→ ① 评测基准/榜单
       │
       └──(提供配对数据)──→ ④ sim-real 消融研究
```

| 时间 | 并行推进 |
|---|---|
| **Q1** | ② 工具 MVP + ③ 数据采集（500 条） |
| **Q2** | ② 开源发布 + ③ 质量打磨 + ④ 配对采集启动 |
| **Q3** | ③ 数据集 v1 发布 + ① 榜单 v0.1（邀请试跑） |
| **Q4** | ④ 消融结论 + ① 榜单首期 + 技术报告 |

**一句话总结**：② 花小钱换话语权，③ 花人力换稀缺资产，① 借别人的模型换行业节点，④ 用"两边都有"换方法论权威。四件事互相喂养，但都不需要和任何人比数据量。

## 四、15 人分工与预算配比

| 岗位 | 人数 | 归属 |
|---|---|---|
| 采集工程师（系统/标定/同步） | 1 | 采集 |
| 操作员（含 1 名组长） | 4-5 | 采集 |
| 仿真工程师（Isaac Sim） | 2-3 | 生产 |
| 数据工程师（质检管线/入库/工具开发） | 2 | 数据 |
| 算法工程师（ACT/DP 基线 + π0 LoRA + 消融实验） | 3 | 模型 |
| 评测/平台（盲评执行、榜单运营、对外发布） | 1 | 评测 |

预算大致配比（按年度总预算）：

- **人力 70-75%**
- **存储 + 算力 15%**：VLA 只做 LoRA，用租卡（1-4×A100 按需），不买 8 卡机自建
- **硬件耗材 5-10%**
- **对外合作/发布 5%**

**明确不做的四件事**（省下的就是预算）：

1. ❌ 不与 OXE/DROID 比规模
2. ❌ 不自研仿真器（用 Isaac Sim，别和 NVIDIA 正面竞争）
3. ❌ 不做全量 VLA 训练（LoRA 起步，季度级）
4. ❌ 不追求本体数量，追求单赛道深度

## 五、12 个月路线（从"没实操过"到"有对外产出"）

| 阶段 | 目标 | 交付物 |
|---|---|---|
| **Q1 跑通闭环** | 500-800 条单一赛道数据，ACT/DP 基线跑通，质检管线落地 | 内部质检报告 + 基线成功率数字 |
| **Q2 做深 + 开源工具** | 聚焦垂直方向，启动 sim-real 配对采集与消融实验；质检工具首个开源版本 | GitHub 工具包 + datasheet v1 |
| **Q3 发布** | 数据集 v1 + 基线权重 + 评测基准 v1，邀请 3-5 家高校/公司试跑 | 榜单首期 + 外部使用案例 |
| **Q4 收口** | 技术报告/论文，v2 数据迭代，正式运营榜单 | 报告 + 新增合作方 |

## 六、影响力度量（别用"采了多少条"考核）

- 外部团队用你的数据训练并**公开报告结果**的数量
- 评测榜单**参与的团队数**
- 工具包的 GitHub star / pip 安装量
- 论文引用 / workshop 邀请 / 厂商合作请求
- 招聘时的候选人主动投递量

## 七、最重要的一句话

团队现在最缺的不是数据量，是"跑通闭环"的经验。前 500 条数据的主要产出不是数据本身，是**团队能力**——一旦闭环跑通，数据会变成可复制的工业品；跑不通，采 5 万条也只是一堆无法验证的硬盘占用。

所以建议 Q1 只设一个目标：用 500 条数据跑通"采集 → 质检 → 入库 → ACT 训练 → 仿真+真机评测"的完整链路，同时产生第一份可对外展示的 datasheet。这份能力比数据值钱。

## 八、待明确的输入

选定"垂直赛道"前需要确认的团队现状：

- 手上具体有哪些本体（单臂/双臂、型号、自由度）
- 遥操作方式（VR / 主从 / 动捕）
- 是否具备力/触觉传感器
- 主要任务域（桌面操作 / 工业 / 家庭 / 移动操作）
- 现有 Isaac Sim 资产完整度（场景、物体、机器人模型）
